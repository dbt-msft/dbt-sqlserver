Fix an incremental `--full-refresh` intermittently failing with `Msg 15135` (*Object is invalid. Extended properties are not permitted on '<schema>.<table>', or the object does not exist*) on a table that plainly exists, before any rebuild work. The in-progress marker resolved its object by two-part name without selecting the model's database first, so it read whichever database the connection was last left on; off-database `OBJECT_ID` returns `NULL`, which both satisfies the `if not exists` guard and makes `sp_addextendedproperty` reject the same name, so the statement cannot succeed - and a retry that finds the connection elsewhere does. `sqlserver__assert_no_incomplete_full_refresh` shared the defect but had no proc to fail it: its count came back `0`, read as *no marker*, so the check that refuses an append onto a half-built table could permit one. Both statements now emit `USE <database>`, pass quoted, qualified names to `OBJECT_ID`, and pin the `sys.extended_properties` lookup to `class = 1 and minor_id = 0`.
