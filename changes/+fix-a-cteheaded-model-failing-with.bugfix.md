Fix a CTE-headed model failing with `Attempt to use a closed connection` instead of its real error. Such a query has its shape read by describing it rather than executing it, and that describe used `sp_describe_first_result_set`, which raises when it cannot describe a query. Handling a raised error closes the connection, so the fallback that then executed the query failed on the closed handle, and the real error survived only at debug level in `logs/dbt.log`. Two things hit this: a model referencing a column or object that does not exist upstream (`Msg 207`/`208`), which to anyone reading a scheduler's task log looked like a network fault; and a query the procedure declines to describe but which executes fine, such as one run with `SET STATISTICS XML ON` (`Msg 11541`), which never got its fallback at all. The describe now uses `sys.dm_exec_describe_first_result_set`, which reports the same failures as rows instead of raising, so the connection stays open: a declined query executes as intended, and a query that does not compile fails executing, at no cost, with its own error. Affects contract-enforced models and snapshot staging queries on every materialization.
